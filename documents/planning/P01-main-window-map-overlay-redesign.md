# P01 主畫面地圖滿版與浮層改版規劃

## 背景與動機

這次改動不是單一 widget 換樣式，而是要重組主畫面的視覺骨架：

- 主地圖要成為整個主畫面的主視覺
- 右上、右下、左下區塊要保留，但改成疊在地圖上的半透明浮層
- 浮層需要有類似側邊欄的視覺縮放概念
- 背後任務邏輯、資料流、MiR API 與既有 signal/slot 盡量不變

目前 `ui_main.py` 以大量固定 `QRect` 與固定尺寸組出畫面，`main.py` 又直接依賴這些 widget 幾何位置處理地圖、marker 與點擊。若不先分階段，容易在一次改動中同時碰到版面、座標、overlay 層級與既有互動，增加回歸風險。

## 總體目標

完成後，使用者打開主畫面時，會看到地圖成為整個主要內容區的背景，右上、右下、左下資訊與操作區以半透明浮層疊在地圖上，原有任務與狀態操作流程維持不變。

## 影響範圍

| 模組 | 主要檔案 | 改動類型 | 說明 |
|---|---|---|---|
| UI Application Shell | `main.py`, `ui_main.py` | RXX | 重組主視覺容器、overlay 佈局、樣式與幾何管理 |
| Site Configuration and Runtime Mapping | `main.py`, `site/*.json` | RXX | 只允許讀取既有地圖資產與校正資料，不更動 schema |
| MiR API Adapter | `functions.py` | — | 不改 API 呼叫與資料流 |
| Task Scheduler | `task_thread.py` | — | 不改任務派送流程 |
| Persistence Layer | `TaskDBManager.py`, `UserDBManager.py` | — | 不改資料結構與狀態流轉 |

## 現況摘要

- `frame_map` 與 `label_map_1` 為固定尺寸，無法直接承接整個主要內容區。
- 右側任務設定、右下清單、左下通知與地圖下方狀態列目前不是 overlay，而是分散在不同固定座標區塊。
- 地圖 overlay 目前只有機器人 marker 圖層，做法是透明 `QLabel` 疊在 `label_map_1` 上。
- 地圖座標轉換與點擊處理依賴硬編碼比例，視覺重組後需要避免幾何失真。

## 已確認邊界

- 這次只做視覺改動，不新增地圖滾輪縮放、拖曳平移、雙擊 reset。
- 盡量保留既有 widget、signal/slot、資料查詢與任務操作流程。
- 不主動重寫 MiR 狀態輪詢、任務邏輯或 DB 流程。

## 未確認假設

- 「浮層縮放」目前先解讀為：浮層會依視窗大小切換正常/緊湊尺寸，或以統一縮放比例調整 padding、字級與控制項尺寸；不預設加入使用者可拖拉的自由縮放控制。
- 若後續希望讓使用者手動展開/收合右側面板，該部分可能需要改列 FXX，而不只是 RXX。

## P1 — 主畫面骨架重組

### 目標

將主畫面改為「地圖背景主導」的版面骨架，但先不搬動右上、右下、左下內容的內部邏輯。

### 技術方向

- 以 `MainWindow` 現有 central widget 為基礎，建立單一主內容容器。
- 讓主地圖所在區域接手整個主要內容區，不再受 `frame_map` 固定尺寸限制。
- 保留 `label_map_1` 與既有地圖載入流程，優先改容器與佈局，不先替換為新的互動元件。
- 把未來要疊在地圖上的區塊先預留 overlay anchor 區域。

### 使用者確認方式

- [x] 開啟主畫面時，地圖背景已經吃滿主要內容區，而不是只停留在左側固定框內。
- [x] 視窗最大化與還原時，地圖仍維持主視覺，不會露出大片空白區或被原本右側黑底區切斷。
- [x] 不進行任何操作時，原有機器人位置 marker 仍能顯示在地圖上。

### 依賴關係

- 後續所有 overlay 重掛都依賴此階段完成的主容器骨架。

## P2 — Overlay 區塊重新掛載

### 目標

把右上狀態區、右下待執行任務清單、左下通知與地圖輔助區塊，改成疊在地圖上的浮層，同時保留既有 widget 與事件綁定。

### 技術方向

- 將既有 widget 重新分組為三個 overlay 容器：
  - 右上：標題、狀態、Mission、起始點/目的地/任務內容、主要按鈕
  - 右下：待執行任務清單與操作按鈕
  - 左下：通知紀錄、地圖點擊開關、離線/心跳摘要
- 既有 widget 優先保留，只調整 parent、layout、幾何策略與樣式。
- 地圖下方若仍有與地圖密切相關的狀態元件，統一收進左下或底部浮層，不保留裸露在地圖外的獨立白底區。

### 使用者確認方式

- [ ] 右上、右下、左下三個區塊都還在，而且功能位置與草稿方向一致。
- [ ] 可以照舊點選起始點、目的地、任務內容下拉選單與按鈕，不需要重新學操作流程。
- [ ] 待執行任務清單仍可正常顯示資料，通知紀錄仍能持續更新。

### 依賴關係

- 依賴 P1 的滿版地圖容器。
- P3 的樣式與縮放規則會套用到這些 overlay 容器。

## P3 — 浮層縮放與視覺主題

### 目標

建立半透明浮層樣式與視窗尺寸對應的緊湊化規則，讓畫面在不同視窗尺寸下仍維持可讀性與草稿風格。

### 技術方向

- 為三個 overlay 容器建立一致的半透明背景、邊框、陰影與字色主題。
- 採用「容器分級縮放」而不是地圖互動縮放：
  - 大尺寸：完整資訊與標準間距
  - 中尺寸：縮小 padding、字級與部分欄位高度
  - 小尺寸：進一步壓縮間距，必要時允許表格高度與訊息區高度縮短
- 不在本階段新增新的資料邏輯；只調整 widget 尺寸政策、字體、margin、spacing 與顏色。

### 使用者確認方式

- [ ] 主畫面看起來已是半透明浮層疊在地圖上，而不是原本分離的白底/黑底拼接畫面。
- [ ] 視窗從大到小調整時，右上、右下、左下區塊會跟著變緊湊，但文字與按鈕仍可辨識與操作。
- [ ] 不需要使用滑鼠滾輪縮放地圖，也能達到你要的「側邊欄式縮放感」。

### 依賴關係

- 依賴 P2 已完成 overlay 分區，才能對容器整體套用樣式與尺寸規則。

## P4 — 回歸驗收與幾何校準

### 目標

在不改背後邏輯的前提下，確認新畫面骨架沒有破壞地圖點位、marker、任務清單與通知流程。

### 技術方向

- 檢查 `label_map_1`、`label_car_overlay`、點擊模式與 marker 繪圖是否仍對齊。
- 驗證因容器重組引入的幾何偏移，必要時只做最小量校準，不重寫座標邏輯。
- 清理與新 layout 衝突的硬編碼 `setGeometry()` 或尺寸限制。

### 使用者確認方式

- [ ] 機器人 marker 位置仍落在正確地圖區域，不會因為滿版後明顯偏移。
- [ ] 啟用地圖點擊後，原有地圖點擊流程仍能運作，不會點到錯誤區域。
- [ ] 新增任務、查看待執行任務、閱讀通知紀錄等既有流程都能照常操作。
- [ ] 關閉再重新開啟程式後，主畫面仍穩定載入新版視覺骨架。

### 依賴關係

- 依賴 P1-P3 完成後的最終畫面骨架。

## 主要風險

1. `ui_main.py` 目前大量使用固定座標，若只局部改幾個元件，容易留下互相覆蓋或 resize 後錯位的殘留問題。
2. `main.py` 對地圖與 overlay 的幾何假設很多，尤其 marker 與點擊比例是硬編碼，容器改動後可能需要最小量校準。
3. 待執行任務清單與通知區塊若只做透明化、不改容器尺寸政策，可能在小視窗下難以閱讀。
4. 若後續臨時加入「可展開/收合」或「手動縮放」控制，工作性質會從單純重構轉為帶互動設計的新功能。

## 驗收準則

- 地圖成為主畫面的主要背景，右側舊式拼接版面消失。
- 右上、右下、左下區塊完整保留，且能浮在地圖上顯示。
- 浮層為半透明，視覺風格一致。
- 不新增地圖滾輪縮放、拖曳平移、雙擊 reset。
- 任務新增、任務列表、通知紀錄、狀態顯示與 marker 顯示皆維持原行為。

## 建議後續接棒

1. P1 已完成，下一步以 `ddd-doc` 起草 P2 對應的 RXX 文件。
2. 後續依序為 P2、P3、P4 各自建立 RXX 文件並逐階段驗收。
3. 若在 P3 之前明確決定加入使用者可手動展開/收合浮層，需重新審視 P3 是否改列 FXX。
